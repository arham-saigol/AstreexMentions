# Brand surfaces and voice

Marketing and product language share one character: observant, composed, decisive, and exact. Marketing can be more editorial; product copy is more operational. Neither becomes breathless.

## Marketing composition

The website should demonstrate the relief of moving from noise to signal. Build an editorial proof sequence, not a catalog of equal-weight feature blocks.

1. **Promise:** one outcome-led headline, one clarifying sentence, one primary CTA, and a quiet secondary action when needed.
2. **Evidence:** make a credible Astreex mention stream, categorization moment, or review workflow the visual protagonist. Product evidence outranks abstract decoration.
3. **Method:** show how keywords, sources, categories, views, and digests create a repeatable review habit. Vary composition by information, not for spectacle.
4. **Trust:** use real source coverage, product limits, security facts, testimonials, or customer proof only when they are verified. Never fabricate logos, quotes, or activity.
5. **Decision:** make pricing and the next step easy to compare. FAQ contains only objections or constraints that materially affect purchase.

Use one substantial solid-cobalt plane or signal-rail composition as a memorable brand moment, balanced by quiet neutral space. Avoid a boxed preview inside every section. Screenshots and demos should use the actual shared product language and plausible data; label illustrative data without surrounding it with legalistic explanation.

Navigation is restrained and stable. Footer copy is short. Blog and changelog pages favor editorial reading measure, honest dates, and clear hierarchy over a second marketing homepage.

## Interface voice

Write for a capable user who wants to act.

- Lead with the object or outcome: “Mentions,” “Save view,” “Reddit needs attention.”
- Use sentence case and familiar verbs. Labels are usually one to three words.
- State the current truth, consequence, and next action in that order when an explanation is necessary.
- Name sources and domain objects consistently: **mention, source, keyword, category, saved view, digest, monitoring**.
- Use **conversation** for the human exchange and **signal** as the brand metaphor. Do not rename a stored domain object “signal.”
- Say **categorized with AI** only where the mechanism affects trust or choice. Do not use AI as an adjective for unrelated features.
- Prefer “couldn't” to “failed to” in user-caused recoverable states; reserve technical wording for diagnostic surfaces.
- Use numerals for counts and limits. Use exact dates, prices, retention, and billing terms where ambiguity costs trust.

### Remove-before-adding test

Before adding a subtitle, helper, eyebrow, badge, or notice, ask:

1. Does the user misunderstand the control without it?
2. Does it prevent a costly or irreversible mistake?
3. Does it communicate state not visible elsewhere?
4. Does it provide proof needed for a decision?

If every answer is no, omit it. Placeholder text is an example, not a replacement for a label. Accessibility text may be visually hidden and is never subject to this removal test.

## Marketing voice

- Make a specific promise, then support it with concrete product behavior.
- Use short declarative sentences and active verbs: find, review, answer, save, track, catch.
- Prefer human stakes over platform mechanics: “Catch the bug report while the thread is still active” beats “AI-powered real-time social listening.”
- Use confidence through precision. Qualify what depends on source APIs, cadence, plan limits, or configuration.
- Keep headline language distinctive but immediately comprehensible. One metaphor per section is enough.

Avoid filler and inherited SaaS language: _seamless, effortless, powerful, unlock, supercharge, revolutionize, game-changing, all-in-one, cutting-edge, leverage,_ and _single pane of glass_. Avoid “never miss a mention” unless the collection contract can literally guarantee it.

## State copy patterns

| Situation                | Pattern                     | Example                                                                     |
| ------------------------ | --------------------------- | --------------------------------------------------------------------------- |
| Empty                    | Absence + resolving action  | “No mentions match this view. Clear a filter or choose another saved view.” |
| Loading                  | Object being prepared       | “Loading mentions…”                                                         |
| Pending                  | Present participle          | “Saving view…”                                                              |
| Success                  | Completed result            | “View saved”                                                                |
| Recoverable error        | What did not happen + retry | “The view wasn't saved. Try again.”                                         |
| Configuration            | Object + required action    | “Connect Reddit to start monitoring this keyword.”                          |
| Destructive confirmation | Exact object + consequence  | “Delete ‘Launch feedback’? This removes the saved view, not its mentions.”  |

Keep these as structural patterns, not a phrase library. Match the real backend behavior.

## Authentication and billing

- Authentication screens feel like Astreex, not a hosted widget dropped on a blank page. Apply the shared type, color, geometry, and focus language through the provider's supported appearance API.
- Ask for the minimum information. Put privacy or terms copy where consent occurs, not as ambient reassurance.
- Billing copy names price, cadence, immediate charge, trial, renewal, taxes, cancellation, and access consequence when applicable. Never let visual minimalism conceal a financial term.
- Plan comparison emphasizes the actual variable—usage, keywords, seats, or retention—rather than repeating “all features” inside every plan card.

## Email

Email is a compact field note, not a miniature app card.

- Use the same solid brand, ink, status, and category colors through email-safe exact values.
- One-column layout, `560–600px` maximum, generous outer margin, and a single primary action.
- Start with why the message matters. Keep account boilerplate and preference controls quiet but reachable.
- Digests prioritize mention excerpt, source, category, and original link. Avoid nesting every item in a bordered card; one outer reading plane and restrained separators are enough.
- Verify light mode, dark mode where supported, Gmail, Outlook, Apple Mail, narrow screens, blocked images, and plain-text meaning.
